# 2026-10-24

## 今天做了什么

- 实现了 gateway 的 `ShouldCache` 逻辑
- 实现了 `HashKey` 的逻辑，在 key 前缀里增加了 chainID

## 遇到的问题与解决

- params 的情况复杂，把实现逻辑都放在 cache 里比较臃肿。把 method 和 params 的判断逻辑单独抽到了一个 helper 函数 `resolveBlockRef` 里
- 组建 cache key 时需要对参数做归一化处理：统一大小写、去除 JSON 里多余的空格（只去除双引号外的）、去除多余的前导 0
- blockNumber 省略和显式写 `latest` 结果相同，让两者共享同一个 key，以降低 cache miss 的概率
- cache key 里加入 chainID，避免以后支持多链时再做兼容改动

## 学到的概念

- 各个方法的参数类型；位于最后一个位置的 blockNumber 参数可以省略，默认值是 `latest`
- 区块参数可能是 blockNumber（字符串），也可能是 object（如 `{"blockHash": "0x..."}`）
- blockHash 固定是 32 字节的十六进制
- Gateway 以后可能需要支持多链，需要提前做兼容处理
- JSON-RPC params 里，双引号外的空格不影响语义；blockNumber、blockHash 是十六进制，大小写不影响含义
